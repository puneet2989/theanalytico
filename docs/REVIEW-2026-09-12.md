# Design and build review, 12 September 2026

Reviewed by running the site locally (`python3 -m http.server`) and driving it in headless Chromium at 1440×900 and 390×844. All six pages loaded, every section scrolled, computed styles and network payloads measured. No console errors and no failed requests on any page.

Findings are grouped into four phases. Each item states the defect, the evidence, the file to change, and the acceptance test.

## Baseline measurements

| Metric | Value | Note |
|---|---|---|
| First contentful paint | 172ms | Healthy |
| DOM nodes (home) | 433 | Healthy |
| Mobile first-load transfer | 968KB | Too heavy, see P3-1 |
| Mobile page height (home) | 11,868px | Excessive for the content volume |
| Console errors | 0 | Across all six pages |
| Untracked video in `assets/video/` | ~22MB | Redundant after the sprite-sheet rewrite |

The motion engineering is sound. The scroll-scrubbed hero morph, the module architecture in [main.js](../assets/js/main.js), the cleanup contracts and the `matchMedia` gating all hold up. The defects below are layout, typography, content governance and payload, not animation quality.

## Phase 0: launch-blocking risk

### P0-1 Preview site is fully crawlable while serving fabricated content

`grep -c 'name="robots"' *.html` returns **0 for all seven HTML files**. [robots.txt](../robots.txt) currently reads `Allow: /` with only `/api/` disallowed.

The site simultaneously serves a fabricated testimonial set ("Aoife M., Practice Owner, Accountancy"; "Declan R., Owner, Wellness"), a fabricated metric ("+39% organic sessions in six months") and a fabricated volume claim. CLAUDE.md requires both a blanket crawl disallow and a per-page `noindex` for exactly this reason.

**Change**
- Add `<meta name="robots" content="noindex, nofollow">` to the `<head>` of `index.html`, `services.html`, `work.html`, `insights.html`, `about.html`, `contact.html` and `logo-options.html`.
- Replace the body of `robots.txt` with `User-agent: *` / `Disallow: /`.
- Add both reversals to [PLACEHOLDER-CONTENT.md](../PLACEHOLDER-CONTENT.md) as launch-checklist items.

**Accept when** every page returns the `noindex` meta and `robots.txt` disallows all, and both are listed in the launch checklist.

### P0-2 Visible copy contradicts the worldwide positioning

Three instances read as locally scoped, which CLAUDE.md prohibits in visible copy:

| File | Line | Current text |
|---|---|---|
| `index.html` | 157 | "Most **local businesses** need a site that converts first" |
| `about.html` | section "Who we work with" | "**Local businesses** where one person carries most of the decisions" |
| `about.html` | `<title>` | "About TheAnalytico — **Dublin** Web Design, SEO and AI Studio" |

Dublin belongs in the JSON-LD `address` and the contact details only. The closing CTA line "Based in Dublin, working with clients anywhere" is fine and should stay.

**Change** rewrite the three strings to describe the client type without geography. "Owner-led businesses where one person carries most of the decisions" preserves the intended meaning. Retitle `about.html` to drop Dublin.

**Accept when** no visible copy on any page scopes the offer to a city, country or "local business", and the JSON-LD still carries `addressLocality: "Dublin"`.

### P0-3 The Lighthouse KPI advertises a failing score

The KPI row states **"75 — average Lighthouse performance score"**. 75 is a failing Lighthouse score, and the project's own non-negotiable is 95+ on every page. An agency selling SEO publishing a 75 undercuts the entire pitch.

**Change** either replace with a real measured figure once the site hits its 95+ target, or drop this KPI and keep three. Do not invent a higher number: the existing placeholder rules require plausible values, and this one is verifiable by anyone with a browser.

**Accept when** the KPI row contains no self-reported score below the project's own quality bar.

## Phase 1: typography and page structure

### P1-1 Section headings are smaller than the headings nested inside them

Computed font sizes on the homepage at 1440px:

| Element | Computed size |
|---|---|
| `h1` hero | 92px |
| `h2` "Four ways we get you found and chosen" | **26.9px** |
| `.section__lead` directly beneath it | 22px |
| `h3` "ArdLens" / "Call" / "Plan" | **40px** |

**Root cause.** [base.css:38-49](../assets/css/base.css#L38-L49) sets `font-family`, `color`, `font-weight`, `letter-spacing` and `line-height` for `h1`–`h6` but sets no `font-size`. The `--fs-h2` token is defined at [tokens.css:94](../assets/css/tokens.css#L94) and is referenced **nowhere in the stylesheet**. Grep confirms: `--fs-h1`, `--fs-h3` and `--fs-h4` each appear in `components.css`; `--fs-h2` appears only in its own definition. Section H2s therefore inherit the browser default `1.5em`.

Card H3s look correct because their component rules set explicit sizes. The hero H1 looks correct because `.hero__title` sets `--fs-display`. The H2 is the only heading level with no size rule, which is why it collapses.

**Change** add explicit `font-size` rules to `base.css` binding each heading level to its token: `h1` to `--fs-h1`, `h2` to `--fs-h2`, `h3` to `--fs-h3`, `h4` to `--fs-h4`. Then audit `components.css` for component rules that need to keep their own override and leave those alone.

**Accept when** every section H2 computes to at least 48px at 1440px, no H3 on the page is larger than the H2 above it, and the existing card headings are unchanged.

### P1-2 Six duplicate CTA blocks break the scroll rhythm

`.section__actions` renders six times on the homepage, at lines [159](../index.html#L159), [217](../index.html#L217), [259](../index.html#L259), [296](../index.html#L296), [329](../index.html#L329) and [377](../index.html#L377), plus the hero pair at [147](../index.html#L147) and the closing pair at [419](../index.html#L419). `services.html` repeats the pattern under its hero.

Two problems compound:

1. **Placement.** [components.css:463-469](../assets/css/components.css#L463-L469) positions the block immediately after the heading and lead, so it sits *between* the section title and the section content. The services grid, the work cards, the KPI row and the testimonial carousel are each pushed a full button-row lower.
2. **Repetition.** "Contact Us" appears eight times on one page, including under "What clients say" and under "Numbers so far", where it interrupts rather than converts.

**Change** remove the `.section__actions` block from the What We Do, Selected Work, How It Runs, Numbers, Testimonials and Insights sections. Keep the hero pair and the closing CTA pair. The per-section trailing links that already exist ("View all services", "See all work", "Read all insights") are the correct in-section CTA and should remain.

**Accept when** the homepage carries exactly two `.section__actions` blocks, and each section's content begins directly under its lead paragraph.

### P1-3 Sections are mostly empty space

`--section-pad-y` is `clamp(72px, 3vw + 32px, 96px)` top and bottom, but several sections render 300px or more of dead vertical space between the rounded top edge and the first content. Combined with P1-1 and P1-2, the result is a page where content occupies a minority of each viewport.

**Change** after P1-1 and P1-2 land, re-measure. The heading size increase and the CTA removal will absorb much of the gap on their own. Then tighten any section whose first content still sits more than ~160px below its top edge.

**Accept when** mobile homepage height drops below 9,000px and no section shows more than 200px of empty space above its first content element.

## Phase 2: mobile and header

### P2-1 Mobile hero renders as an empty black screen

At 390×844 the hero morph canvas draws roughly 200px tall at the top of the viewport, the stage caption overlaps it, and the remaining ~600px of the first screen is solid black with nothing in it. The morph itself works and the captions advance correctly on scroll; the stage is simply not sized to the viewport it sits in.

This is the first thing a phone user sees, and phones are the majority of traffic for every sector in the portfolio.

**Change** size the mobile morph stage to fill the available viewport height below the header, and move the stage caption clear of the canvas rather than over it. The mobile sprite sheet (`hero-morph-sprite-mobile.webp`, 170KB, already loading correctly) does not need regenerating.

**Accept when** at 390×844 the hero fills the first viewport with no black band taller than 100px, and the stage caption does not overlap the rendered form at any scrub position.

### P2-2 Pinned header pill is too transparent over light content

On `work.html` the project spec labels (SECTOR, BUILD) are readable *through* the pinned pill. On `about.html` card body copy shows through. `backdrop-filter: blur(16px)` alone does not separate the pill from light backgrounds; it needs a more opaque base layer behind the blur.

**Change** raise the pinned pill's background opacity over light sections while keeping the blur. `--surface-85` already exists in [tokens.css:61](../assets/css/tokens.css#L61) and is the obvious candidate.

**Accept when** no page content is legible through the pinned pill at any scroll position on any of the six pages, and the blur effect is retained.

### P2-3 Testimonial carousel clips card text on mobile

At 390px the carousel cards are cut at both viewport edges mid-word: "it finally looks like the…", "M., Practice Owner". A peek carousel should show a deliberate slice of the next card, not truncate the active one.

**Change** constrain the active slide to the viewport width minus the gutter at mobile widths, so the peek falls on the neighbouring card only.

**Accept when** at 390px the active testimonial card is fully readable, including its attribution line, and only the adjacent card is clipped.

### P2-4 Reconsider collapsing "the" from the pinned wordmark

[header-pill.js:23-31](../assets/js/modules/header-pill.js#L23-L31) documents this as deliberate: the first line of the wordmark collapses on pinning, leaving "Analytico". The corresponding CSS is at [components.css:115](../assets/css/components.css#L115).

This is a design decision rather than a defect, so it is flagged for a call rather than specified as a fix. The consequence is that in the pinned state, which is where users spend nearly all their time, the brand reads as "Analytico" and the orange "the" that carries the only accent colour in the header disappears. The footer shows the full "theAnalytico" lockup, so the two do not agree.

**Options** keep the full wordmark at a reduced scale, or keep the collapse and accept the shortened brand. Decide before further header work.

## Phase 3: payload and motion upgrades

### P3-1 A 134KB WebGL library downloads on every phone and is never used

[flowmap-trail.js:49](../assets/js/modules/flowmap-trail.js#L49) statically imports `../vendor/ogl.mjs` at module top level. The module then bails at [line 130](../assets/js/modules/flowmap-trail.js#L130) when `isMobile` and at [line 129](../assets/js/modules/flowmap-trail.js#L129) when `reduced`. Because the import is static, the browser fetches and parses all 134KB before the guard ever runs. `ogl.mjs` is the single largest script on the page, larger than GSAP.

**Change** convert to a dynamic `await import('../vendor/ogl.mjs')` placed after the `reduced` and `isMobile` guards.

**Accept when** a 390px-wide load requests no `ogl.mjs`, total mobile transfer drops below 840KB, and the desktop cursor trail still works.

### P3-2 Remove redundant video and correct the stale spec

`assets/video/` holds roughly 22MB of untracked `.mp4` files, including `hero-morph.mp4` (4.9MB), `reel-teaser-1.mp4` (5.8MB) and `reel-teaser-2.mp4` (5.4MB). The hero now renders from a sprite sheet, not a video: see [hero-morph.js:32-42](../assets/js/modules/hero-morph.js#L32-L42).

CLAUDE.md still documents the hero as a blob-URL video under "Effect inventory to implement", item 1. That description no longer matches the implementation and will mislead the next agent that reads it.

**Change** delete the unreferenced `.mp4` files after confirming nothing loads them, and rewrite CLAUDE.md effect item 1 to describe the sprite-sheet approach.

**Accept when** no unreferenced video remains in `assets/video/` and CLAUDE.md describes what the code actually does.

### P3-3 Three unrelated colour systems on one page

The homepage runs a near-black hero, then the cream/blue/grey token palette, then four service cards using `--gradient-web` (navy), `--gradient-seo` (green), `--gradient-paid` (maroon) and `--gradient-ai` (purple) from [tokens.css:80-83](../assets/css/tokens.css#L80-L83). None of those four hues relate to `--accent` (terracotta) or `--accent-2` (periwinkle). The hero-to-cream transition is also an abrupt cut rather than a designed handover.

**Change** rebuild the service card gradients from the accent pair so they read as one family, and design the hero-to-first-section transition rather than butting the two against each other. The contrast ratios documented in the token comments must be preserved: each card currently passes 4.5:1 comfortably and any replacement must be re-checked.

**Accept when** every service card gradient derives from `--accent` or `--accent-2`, all four still exceed 4.5:1 for white text, and the hero-to-section boundary is a deliberate transition.

### P3-4 Layout patterns worth adding

The site already has scroll-scrubbing, which is the current idiom. What is missing is layout that makes the scrubbing feel purposeful rather than decorative. Two candidates, in priority order:

1. **Pin the services section.** Pin one visual and swap the copy beside it as scroll advances through the four pillars, replacing the four-card grid that currently reveals all at once. This reuses the hero morph's narrative-progression pattern and suits the "pick one or stack them" message.
2. **Move simple reveals to native scroll-driven animation.** `animation-timeline: view()` handles the fade-up and stagger cases without JavaScript and runs off the compositor. Candidates: `reveal-stagger`, `heading-mask`, `tilt-cards`. This trims JS weight and removes ScrollTrigger instances.

Both are larger pieces of work than anything above and should follow phases 0 to 2.

## Suggested order

Phase 0 first and on its own, because it is the only launch-blocking group and it is small. Phase 1 next: P1-1 and P1-2 together will change the look of every page more than anything else on this list, and P1-3 depends on both landing first. Phase 2 after that. Phase 3 last, with P3-1 pulled forward if a performance pass is wanted early, since it is a one-line change worth 134KB.
